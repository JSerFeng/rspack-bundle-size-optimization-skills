# 具体实现的保留与删除证据

系统性 export usage 审计使用本规范。每个高影响目标关联一条或多条具体实现记录，
解释“保留什么、为什么保留、怎样解除、产物是否变化、行为是否保持”。
记录存入当前审计目录，不写入项目业务代码或 skill 自身。可以扩展已有台账字段，
或用独立文件和记录 ID 关联；证据共享用链接，避免复制整图。

## 1. 具体实现

以函数、类、顶层初始化、数据字段或内部依赖子树为单位，不能仅用包名代表实现。
保存 target ID、implementation ID、compiler/run/buildHash、module ID、resource、
export/member path 和统计范围。实现可不是公共导出，匿名路径按真实状态记录。

记录源码文本哈希、坐标空间（resource / post-loader / map-source）、范围、范围哈希
和 AST 名称；原资源与转换后文本都可保留，但不能混用行号。生成或虚拟代码缺少 AST
范围时使用可复核的片段或结构证据，注明局限，不伪造精确位置。

先确认该实现确实在 before 产物中存在。没有发射的未使用导出，不能计作新优化空间。
实现下的独占依赖与被其他实现共享的依赖分开记录，不能把整个包体积当作该实现大小。

## 2. 保留引用与操作

从相关 export/member 的全部入边反向追查，保存 edge ID、origin/target、两端路径、
引用源码和实际消费操作。调用、实例化、枚举命名空间、传递对象、注册和模块级执行
必须区分。源码 owner 只表示语法归属，不能直接替代跨模块使用关系。

遇到别名继续跟踪绑定的读取与修改；对象作为参数传递时继续检查接收方；CJS、动态
import 和合并模块通过 Module Graph 补充，并定位成员源码。所有分支、分页和未知
关系进入同一记录，不把匿名边或查询终点当作业务无使用的证明。

记录导致保留的具体操作及其源码范围，区分 native 事实、模块图事实和源码推断。
例如整对象枚举会使静态读取范围扩大，但必须找到真实枚举操作，不能只凭 CJS 后缀
或 namespace import 下结论。无法证明因果关系时记录待查分支与下一步。

## 3. 等价修改

保存单变量改动或 before/after 伪代码、修改文件及预期消除的保留原因，明确预计
消失/收缩的实现 ID。API、完整数据集合、对象身份、getter、注册与初始化时序等约束
按实际代码列出，不用笼统的“功能不变”代替。

分别记录 package 作者 sideEffects、Rspack override 和 PURE 标注是否改变、为何安全。
选择已有 ESM 入口时确认版本、条件解析和消费者；不能假定公共导出名相同就完全等价。
发现必须保留的实现时写明必要调用或副作用证据，此环可记录“不修改及原因”。

## 4. 产物证据

before 与 after 均保存 compiler/build、资产清单、JS 哈希、构建设置及使用的 map 身份。
比较相同用户统计范围中的全部资产，不只检查原 chunk 文件名。跨构建 module/chunk ID
可改变，以资源、文本身份及解析关系建立对应，不能按 basename 合并不同实例。

优先使用实际产物和与其同构建的 source map 将生成代码对应到实现范围：

1. 核对 sourcesContent 哈希，判断它对应原资源、post-loader 或另一个虚拟 source。
2. 在该份文本上提取实现范围，匹配映射段；统计有界生成范围，不无条件延伸映射到行尾。
3. 核对 after 的所有相关资产，检查实现是否仍在其他 chunk、worker 或安装实例中。
4. 用 `usedExports` 的变化、可确认的结构/独有常量等交叉核对。名称可能被压缩，常量
   可能被折叠或共享，零映射也可能来自 map 缺口，这些信号均不能单独证明删除。

缺 map、内联、代码共享或范围歧义时列出受影响资产和未归因范围；按需要补充映射或
结构诊断，不把诊断配置的体积当正常生产收益。仍无法验证时，产物删除状态保持未知。
某个 source 还出现在 map 中，也不证明其中所有函数都留在输出代码中。

将产物判定分为 `removed`、`reduced`、`retained`、`moved`、`unknown`，保存判定依据。
原结构被重写不意味着全部相关实现被删除。仅移动、去重或模块包装变小，不能冒充
未使用 export 实现的删除。

映射字节只作归因证据，整项 raw/gzip 净收益由同方法完整资产生产 A/B 给出。不得将
整项差值归给少数示例函数，也不得累加共享子树或独立实验来代替合并构建。

## 5. 行为验证与记录格式

按修改的实际契约验证公共 API、完整数据和相关行为。记录执行命令、环境、结果和
证据文件；生产构建成功不自动证明行为等价。仅改构建入口也需要检查 API 与适用行为。
SSR、浏览器导航、hydration、真实页面请求分别记录是否测试，不互相替代。

每条实现记录至少具备以下字段；字段名可适配既有台账，但语义不可省略：

| 字段 | 内容 |
| --- | --- |
| identity | 实现 ID、所属目标、compiler/build、模块/源码身份、用户统计范围 |
| implementation | 名称/类型、文本与范围哈希、坐标空间、源码范围、独占/共享依赖 |
| retention | 引用边和消费操作、保留原因、补充模块图证据、全部待查分支 |
| change | 单变量改动、预期移除实现、等价约束；或不修改的证据理由 |
| emission | before/after 构建和资产证据、产物判定、未归因范围、完整 raw/gzip A/B |
| behavior | 相关正确性检查、结果、未测试的行为及其对结论的影响 |
| conclusion | 实现结论、候选验证状态、所属目标是否完成、剩余问题与下一步 |

尚未实验的记录，change / emission / behavior 可以注明“未执行及原因”，但不能标为
已验证有效。确认必要或已经被编译器删除的实现不强制实验，必须保留其必要性或原有
删除证据。不能用空字段、unknown 或缺口说明冒充已经执行的调查。

## 完成检查与状态同步

每次产生结论同步实现记录、目标台账和报告；候选已验证但整个目标尚未完成时同时
保存两个状态。证据路径应存在，且所链接内容与字段描述一致；布尔字段不替代证据。

交付前按以下条件核对，不通过的实现或目标继续保留未完成状态：

```text
候选验证完成 =
  具体实现与 before 发射证据可复核
  且 保留引用及实际操作有证据，修改所依赖的消费/副作用分支已处理
  且 修改及相关行为约束得到验证
  且 after 产物判定有依据，完整生产 A/B 使用同一统计范围

可记 export 裁剪收益 =
  候选验证完成 且 有未使用实现的 removed/reduced 证据 且 同口径净收益为正

目标分析完成 =
  选择范围内所有相关实现与引用分支均有结论
  且 没有未执行的调查、未续查 frontier 或影响结论的未知消费/副作用分支
```

局部候选可完成，未涉及的其他实现仍可待分析；不能为获得完成状态缩小原目标范围。
结构扫描、目标语义分析完成和候选验证完成分别计数。包大、导出减少、函数名字消失、
记录条数或某个目标下面有成功候选，均不等于整个目标完成。
